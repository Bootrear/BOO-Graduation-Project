三、CWE 数据契约

先检查真实 CWE 文件的格式、版本、命名空间及结构，再实现解析。初始版本支持实际提供的数据格式，文档明确支持范围。

默认围绕 Weakness 条目构建知识段。Category、View 等其他记录类型应明确排除或单独记录，不能与弱点条目混用。

1. 数据快照清单

每个快照保存独立 manifest，至少包含：
- dataset_name；
- dataset_version；
- snapshot_id；
- source_download_url；
- raw_file_sha256；
- acquired_at；
- acquired_at_basis；
- processed_at；
- parser_version；
- chunker_version；
- preprocessing_config；
- preprocessing_config_sha256。

时间使用带时区的 ISO 8601 格式。

snapshot_id 根据原始文件哈希和处理配置等稳定信息生成。获取时间和本次运行时间不参与稳定 ID 计算。

如果本地文件真实下载时间无法确定：
- acquired_at 可以为空；
- acquired_at_basis 标明 unknown；
- 另行记录系统接收或登记该文件的时间。
不能将当前时间或文件修改时间冒充真实下载时间。

2. 每个知识段的必备字段

- passage_id：稳定、唯一的知识段 ID；
- cwe_id：规范化 CWE 编号；
- title：条目名称；
- field_name：统一的语义字段名称；
- source_locator：原始文件中的字段路径及必要的序号；
- chunk_index：该来源单元内的分段序号；
- source_text：该来源单元解析得到的完整文本；
- text：实际用于检索和阅读的知识段文本；
- source_url：对应条目的可回查 URL；
- dataset_version；
- snapshot_id；
- acquired_at；
- content_sha256；
- entry_status：原始条目状态，如来源提供。

passage_id 的生成规则必须写入文档，并基于稳定来源信息、处理版本、分段序号或内容哈希等生成。不得使用 Python 内置 hash()、随机 UUID 或运行时间生成可复现 ID。

content_sha256 统一基于实际 text 的 UTF-8 字节计算，明确 Unicode 和换行规范。

同一原始快照、相同处理配置重复运行，应产生相同的知识段文本和 ID。运行时间等操作元数据允许不同。

3. 字段映射与语义完整性

建立实际 CWE 路径到语义字段的显式映射，至少覆盖数据中存在的：
- Description；
- Extended_Description；
- Common_Consequences；
- Detection_Methods；
- Potential_Mitigations。

“成因”若没有独立来源字段，应定位到实际描述该信息的原文，保持其真实字段名称和路径。

嵌套结构应保留有助于理解的配对关系，例如：
- 后果的 Scope、Impact 和条件说明；
- 检测方法名称及对应描述；
- 缓解措施的 Phase、Strategy 和描述。

不能将嵌套字段全部拍平成脱离上下文的短语，也不能自行补写安全事实。

缺失字段按缺失处理，记录统计。空文本不得形成知识段。

source_text 是解析后的来源文本，并非原始 XML 字节副本。原始文件通过快照和哈希保留，用于完整回查。

4. 清洗、切分和重复处理

统一编码、Unicode、空白和换行处理，记录具体规则。

优先按来源语义单元切分。超长文本再依据真实分词器和输入预算分段，尽量保留完整句子、编号与适用条件。

记录 Reader 输入中为问题、标题和特殊 token 预留的预算。超长问题和截断情况必须有明确处理规则与运行记录。

重复识别至少区分：
- 同一来源单元的重复解析；
- 不同条目或字段中的相同文本。

跨来源相同文本不能因去重而丢失来源。可以保留独立记录，或显式保留全部来源关系，选择一种简单且一致的实现并记录。

保留处理统计，包括读取条目数、纳入条目数、缺失字段数、空文本数、重复记录数和最终知识段数。

四、DPR 编码与检索

1. 使用匹配的 DPR 问题编码器和段落编码器。
2. 离线生成段落向量，保存索引、向量和 passage_id 映射。
3. 在线加载已有索引，对当前问题编码，返回最多 N 个候选段落。
4. 检索度量与模型保持一致，明确是否使用内积及是否归一化。
5. MMR 使用余弦相似度时，可建立向量的归一化副本，不得无意改变 DPR 检索使用的原始向量或度量。
6. 候选按 passage_id 去重，保持确定性顺序。
7. 返回 passage_id、原文、检索分数、候选排名和来源信息。
8. 索引与原文库必须属于同一快照，加载时检查兼容性。
9. 保存模型标识、revision、分词器、长度配置、向量维度和索引参数。

五、DPR Reader 与候选记录契约

将同一问题分别与候选知识段共同输入 Reader，可批量推理。

必须区分：
- DPR retrieval_score；
- Reader relevance_logit；
- 答案 start_logits、end_logits；
- 后处理得到的 span_score。

以当前使用的模型和库版本为准检查输出。对通常形如 (n_passages,) 的 relevance_logits，验证展平后的每个值与 passage_id 一一对应，禁止未经检查使用 squeeze 导致单候选情况形状错误。

处理有效答案位置、起止顺序、跨度长度和原文映射。排除问题区域、特殊标记和 padding 等无效答案位置。

每条候选运行记录至少包含：
- passage_id；
- retrieval_rank；
- retrieval_score；
- reader_relevance_logit；
- reader_relevance_normalized；
- 候选答案文本；
- 答案对应位置；
- span_score；
- 原文与来源引用。

Reader 结果只计算一次，供 reader_topk、MMR 和普通回答复用。

禁止把 relevance_logit 或归一化分数解释成答案正确概率，也不能将不同问题的原始 logit 直接作为统一的证据充分性阈值。

六、相关性和冗余的明确尺度规则

初始基线采用以下规则，集中实现并供所有入口复用。

1. 相关性归一化

对同一问题的完整有效候选池 C，设 Reader 原始分数为 r_i：

r_min = min(r_i)
r_max = max(r_i)
d = r_max - r_min

设 epsilon＝1e-12，归一化计算使用足够精度：

当 d > epsilon：
Rel_hat(q,i) = (r_i - r_min) / d

当 d <= epsilon：
所有候选的 Rel_hat(q,i) = 0

该规则同样覆盖只有一个候选的情况。

在 MMR 开始前计算一次，整个选择过程中固定。不得每轮对剩余候选重新归一化。

原始 logit 必须保留，用于诊断及同分处理。

2. 段落相似度

从候选对应的 DPR 段落向量计算余弦相似度：

cos(i,j) = dot(v_i,v_j) / (norm(v_i) × norm(v_j))

先将浮点误差导致的结果裁剪到 [-1,1]，再定义：

Sim_hat(i,j) = max(0, cos(i,j))

这样 Rel_hat 和 Sim_hat 均位于 [0,1]。负余弦相似度按零冗余处理，避免给予额外的负相关奖励。

明确这是本项目选择的尺度约定。

3. 异常与冻结

NaN、Inf、零范数向量必须有明确检查及日志，不能静默变成正常分数。模型输出异常应标记查询失败或按事先记录的规则处理。

以上规则不等于模型校准。min-max 处理也可能放大很小的分数差异，需要保留原始分数进行后续分析。

正式调参时只使用开发集。若修改归一化或相似度规则，应重新评估 λ，并更新配置版本。正式测试期间全部固定。

七、Reader Top-5 与逐轮 MMR

1. Reader Top-5

按原始 Reader relevance_logit 降序选择最多 K 段。

同分时依次采用：
- DPR retrieval_rank 升序；
- passage_id 字典序。

2. MMR 的集合定义与选择公式

C 是去重后的完整候选集合。
S 是已选集合，初始为空。
selected_order 单独保存选择顺序。

定义：

R_hat(i,S) = 0，若 S 为空；
R_hat(i,S) = max_{j∈S} Sim_hat(i,j)，否则。

每轮选择：

i* = argmax_{i∈C\S}
     [λ × Rel_hat(q,i) − (1−λ) × R_hat(i,S)]

然后执行：

S ← S ∪ {i*}
selected_order.append(i*)

直到 len(S)＝min(K,len(C))。

每轮加入新段落后，所有剩余候选针对新 S 的冗余值必须正确更新。禁止一次性计算分数并排序取前 K 段。

MMR 同分时依次采用：
- 原始 Reader relevance_logit 降序；
- DPR retrieval_rank 升序；
- passage_id 字典序。

λ 必须在 [0,1] 内。

λ＝0 且第一轮所有 MMR 分数相同时，使用上述同分规则确定首段。
λ＝1 时，选择顺序应与 Reader Top-K 一致。

3. 允许的高效实现

可以预先计算候选间相似度矩阵，并使用增量最大值维护冗余：

新 R_hat(i,S∪{i*})
= max(旧 R_hat(i,S), Sim_hat(i,i*))

在本项目 Sim_hat 非负的约定下，将初始冗余设为 0 即可。

该实现必须与直接遍历当前 S 计算最大值的参考实现等价。

4. 选择日志

每轮至少记录：
- 轮次；
- 选择前的已选 ID；
- 被选 passage_id；
- 原始与归一化相关性；
- 当前最大冗余及对应已选段；
- 本轮 MMR 得分。

返回 selected_order 和对应完整证据记录。

八、普通模式回答与可用入口

普通模式只使用最终选定证据中的 Reader 结果。

明确答案排序规则及其实现位置，避免直接混合未定义尺度的分数。复杂或未校准的置信度组合不能隐藏在代码中。

输出类型包括：
- 抽取答案；
- 相关原文；
- 信息不足或处理失败。

提供抽取文本、证据 ID、来源和上下文。记录回退原因。

“没有候选”“候选不足 K”和“证据不足”分别处理。候选数量足够不能作为证据充分的判断依据。尚未校准的回退规则明确标记。

提供完整 CLI。仓库已有 API 时复用现有结构。

支持：
- 数据处理；
- 索引构建；
- 索引加载；
- 问题查询；
- reader_topk/mmr 策略选择；
- 结构化结果保存。

4. MMR 关键测试

必须包含一个能发现“只算一次分数取 Top-K”错误的例子：

三个候选的原始相关性分别为：
A＝10，B＝9，C＝8。

向量可取：
A＝(1,0,0)；
B＝(0.99,sqrt(1−0.99²),0)；
C＝(0.1,0,sqrt(0.99))。

使用 λ＝0.5、K＝2。

预期：
- Reader Top-K 选 A、B；
- MMR 第一轮选 A；
- 加入 A 后重新计算剩余候选得分；
- MMR 第二轮选 C。

同时验证：
- 空候选；
- K＝0；
- 候选不足 K；
- λ＝0 和 λ＝1；
- 同分选择的确定性；
- 无重复选择；
- 增量最大值实现与直接计算参考实现的选择顺序及分数一致。
