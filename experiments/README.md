## 两组受控对照

| 实验 | 变化项 | 固定项 |
| --- | --- | --- |
| Reader Top-5 vs MMR | 证据筛选策略 | 知识库快照、问题集、DPR 候选集合及顺序、Reader 分数、模型与分词器；初始 N=20，最多选 5 段 |
| 普通模式 vs 增强模式 | 回答组织方式 | 同一问题、同一组 MMR 证据 ID 及顺序、原文、来源与快照 |

两组实验分别回答筛选与回答方式的问题。Reader Top-5 按 Reader 相关性排序，不能用 DPR 检索 Top-5 替代。候选少于 5 段时返回实际数量；空候选、证据不足及无法抽取的情况单独记录。

MMR 使用统一尺度后的 Reader 相关性与候选段落向量余弦相似度；λ、尺度处理及同分规则在开发集确定并冻结。上下文长度是模型工程约束，不加入额外领域评分。增强模式模型、精度、提示词和解码参数须在正式实验前固定。

## 数据与指标

至少 120 道人工核验题，按来源条目分为开发集 80 题、冻结测试集 40 题。详见[标注规范](../data/annotations/README.md)。

| 层级 | 报告指标 |
| --- | --- |
| 检索 | Recall@N：必要支持段进入候选池的比例 |
| 筛选 | Evidence Recall@5、有效知识段比例、平均段间余弦相似度、实际返回段数 |
| 回答 | 人工核验的关键事实正确性、回答完整性、来源支持、无依据陈述比例 |
| 单跨度子集 | 补充 EM/F1，冻结文本规范化及分词规则 |
| 开销 | 召回、Reader、筛选、回答耗时，端到端延迟及内存／显存等资源使用 |

正式运行前固定指标分母、宏／微平均规则、有效知识段判定及人工评分细则。段数少于 2 时，两两相似度记为不适用并报告样本数；无必要支持段的题目应单独标记，不能套用常规召回分母。现有 `evaluation/metrics.py` 仅实现基础证据 precision、recall 和早期字段覆盖，未实现本表全部指标。

分别分析定义、后果、检测、缓解，以及单跨度／综合题。失败原因按数据缺失、召回遗漏、Reader 评分偏差、MMR 漏选、抽取失败、生成误用记录，不以答案流畅程度代替事实核验。

## 记录结构

每次正式运行创建独立目录，以下文件在实际运行时生成：

```text
experiments/<YYYYMMDD-HHMM>_<comparison>_<snapshot>/
├─ config.json
├─ manifest.json
├─ per_question.jsonl
├─ summary.json
└─ notes.md
```

`manifest.json` 至少记录 Git commit 与工作树状态、数据与标注快照及哈希、处理脚本版本、Python 和依赖版本、硬件、DPR 双编码器与 Reader 的模型／分词器 revision、截断长度、候选数、选择数、分数处理、MMR λ、生成模型与精度、提示词及解码参数、随机种子、实际命令和起止时间。

`per_question.jsonl` 保存问题、快照、候选知识段 ID 与 DPR／Reader 分数、答案位置、筛选顺序与得分、最终证据 ID、模式、回答、引用编号检查、人工核验结果、各阶段耗时及异常或回退原因。两种回答模式必须可通过问题与证据记录关联。

`summary.json` 汇总指标与有效样本数，`notes.md` 说明运行条件、失败案例和限制。只提交经过核对且可公开的实验记录；大体积输出放入默认忽略的 `outputs/`。确定性重复运行不得当成独立问题样本。
