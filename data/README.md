# 数据目录规范

当前主知识库为 **CWE 英文原文**，优先处理定义、成因、后果、检测与缓解；NVD、ATT&CK、CAPEC、KEV 仅为已准备的可选扩展。已有原始数据不等于已建成可检索知识库。

本地起始快照见 [SOURCES.md](SOURCES.md)，哈希见 [starter_snapshot_2026-10-20.sha256](starter_snapshot_2026-10-20.sha256)。原始数据、处理结果与索引由 `.gitignore` 排除，克隆仓库不会获得这些文件。

## 目录职责

| 目录 | 内容 |
| --- | --- |
| `raw/` | 官方原始文件，保留来源、版本和获取记录，不改写原文 |
| `processed/` | 按快照组织的知识段 JSONL、来源清单、向量及索引；待 ETL 实现后生成 |
| `annotations/` | 人工核验问题、答案、必要事实、支持知识段与划分清单 |

## 知识段与清单

计划先按语义字段切分，再按模型长度限制对超长字段按完整句子二次切分，尽量保留安全编号、术语和适用条件；规范编码与空白，并识别重复记录。

知识段最低记录如下；这是当前知识段目标数据规范：

| 字段 | 含义 |
| --- | --- |
| `evidence_id` | 知识段 ID，同一快照和切分规则下稳定，包含可区分分块的信息 |
| `source`、`record_id`、`record_type` | 来源、CWE 条目 ID 与记录类型 |
| `field_name`、`text` | 语义字段与原文 |
| `url`、`source_version` | 官方出处及数据版本 |
| `retrieved_at` | 获取时间；现有数据类中尚未实现，接入时可直接记录或通过清单关联 |
| `modified` | 来源提供的修改时间，可为空 |
| `content_hash` | 用于内容变化识别的哈希，待 ETL 实现 |
| `token_count` | 按冻结分词器统计的长度 |

每个快照的 `manifest.json` 计划记录：来源 URL、获取时间、版本与使用条款、原始文件 SHA-256、处理脚本提交号、分段规则、分词器与 DPR 段落编码器 revision、知识段数量、知识段／向量／索引的版本与哈希。必须能由知识段 ID 回查原始条目及字段。

## 更新机制（待实现）

1. 定期检查或手动触发获取，保留新原始文件与版本记录。
2. 按条目 ID、字段内容和哈希识别新增、修改及状态变化。
3. 重新解析变化内容并生成向量，使失效知识段退出当前检索范围。
4. 检查知识段 ID 唯一性、来源可追溯性、知识段与向量及索引的一致性。
5. 检查通过后切换到新版本，保留上一有效版本和处理日志以便回退。

日常问答使用最近一次更新成功的版本，并在每次运行中记录快照。正式实验锁定快照、模型及处理配置，不随日常更新改变；不同实验方法共用相同数据版本。

## 人工核验

问题需保留可接受答案、必要事实与支持知识段 ID。至少 120 题，按来源条目划分开发集 80 题和冻结测试集 40 题。模板或模型生成的问题仅为候选，核验后才能进入正式集合；不得用答案字符串出现替代证据标注。详见[标注规范](annotations/README.md)。
